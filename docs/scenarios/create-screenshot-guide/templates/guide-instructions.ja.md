# 作業指示書: Swagger UI Petstore のスクリーンショット手順書を作成する

## 目的

Playwright CLI を使って、初心者にもわかりやすいスクリーンショット付きの GUI マニュアルを
作成します。このマニュアルは、[Swagger UI Petstore](https://petstore.swagger.io/) で
1 つの API オペレーションを呼び出す方法を、初めての利用者に教えるものです。
`GET /pet/findByStatus` オペレーションを最初から最後まで一通り操作し、各ステップで
スクリーンショットを 1 枚撮影して、その結果を Markdown ガイドとして書き出します。これは
公開されている第三者のデモサイトへの読み取り専用の訪問です。

この指示書から作成された、チェックイン済みのサンプルは
[sample-guide/petstore-swagger-ui-guide.ja.md](../sample-guide/petstore-swagger-ui-guide.ja.md)
で、画像は `sample-guide/images/` 配下にあります。

## 実行ルール

- コマンドはリポジトリルートから実行します。
- プロジェクトローカルの CLI を `pnpm exec playwright-cli` 経由で使用し、インストール済みの
  Playwright CLI Agent Skill に従います。
- すべてのブラウザーコマンドで名前付きブラウザーセッション `create-screenshot-guide` を
  使用し、クリーンアップ時にそれを閉じます。
- CLI が管理する新しいブラウザーを使用します。個人のブラウザーに接続したり、永続プロファ
  イル、保存された状態、Cookie、認証情報を使用したりしないでください。
- 撮影前に `resize 1280 900` で一貫したビューポートを設定し、すべてのスクリーンショットの
  幅をそろえます。
- アクセシビリティスナップショットと、ロールおよびアクセシブルネームに基づくユーザー向け
  ロケーターを優先します。ナビゲーションやページ状態の大きな変化のあとには新しいスナップ
  ショットを取得し、古いスナップショットの一時的な要素参照を再利用しないでください。
- 訪問は読み取り専用に保ちます。オペレーションの展開、**Try it out** の使用、値の選択、
  **Execute** のみを行います。作成、更新、削除、アップロード、認証は行わないでください。
- Cookie や同意のバナーが表示された場合は、ページを覆わないように、撮影前に閉じます。
- すべてのキャプションは、実際に観察した内容に基づいて記述します。Petstore は共有の公開
  サンドボックスであるため、レスポンスボディは動的なものとして扱い、内容が異なることを
  読者に伝えます。

## スクリーンショットのルール

- CLI の `screenshot --filename=<path>` オプションを使って、厳選したスクリーンショットを
  `sample-guide/images/` に保存します。
- ファイル名には 2 桁のステップ番号の接頭辞と短い説明を付けます。例:
  `01-overview.png`、`02-expand-findbystatus.png`。
- 各撮影の前に、対象の要素をビューポートの上部までスクロールし、そのステップのコントロー
  ルが完全に見えるようにします。
- 画像を小さく要点を押さえたものに保つため、（ページ全体ではなく）ビューポートを撮影し
  ます。
- オーバーレイ、バナー、個人情報、無関係なブラウザー UI は撮影しないでください。
- これらの画像は意図的なドキュメント成果物です。保持してください。`.playwright-cli/`
  配下の一時的な出力としては扱わないでください。

## ガイドの構成

技術者でない読者でも従えるようにガイドを記述します。次を含めます:

1. 短い導入: Swagger UI とは何か、対象サイト、読者が達成できること。
2. スクリーンショットが共有デモのある時点のスナップショットであるという注記。
3. 「始める前に」の一覧（ブラウザーとインターネット接続）。
4. 以下の各アクションに対応する番号付きステップを 1 つずつ。各ステップには次を記載します:
   何をするか、スクリーンショット、読者が確認できること。
5. 安全な次のアクションを提案する短い「次のステップ」セクション。

スクリーンショットはステップごとにちょうど 1 枚とし、ステップ見出しの直下に配置して、
`images/01-overview.png` のような相対パスで参照します。

## ウォークスルーの手順

各ステップでスクリーンショットを 1 枚撮影します。

1. **ページを開いて全体を確認する** — `https://petstore.swagger.io/` を開き、Cookie バナー
   があれば閉じて、上部までスクロールします。タイトル（`Swagger Petstore`）、ベース URL
   （`petstore.swagger.io/v2`）、**Authorize** ボタン、**pet** / **store** / **user** の
   タググループを指し示します。
2. **オペレーションを展開する** — **pet** グループで **GET** `/pet/findByStatus`
   （「Finds Pets by status」）を展開します。説明、値 `available`、`pending`、`sold` を持つ
   必須の `status` パラメーター、そして `200` のレスポンス例を指し示します。
3. **Try it out** — **Try it out** をクリックします。`status` フィールドが編集可能になり、
   **Execute** ボタンが表示され、ボタンが **Cancel** に変わることを指し示します。
4. **パラメーターを設定する** — `status` コントロールで `available` を選択します。値が選択
   されていることを確認します。
5. **Execute** — **Execute** をクリックします。生成された **Curl** コマンドと
   **Request URL** を指し示し、`available` が `?status=available` として現れることを説明
   します。
6. **レスポンスを読み取る** — **Server response** を示します: `200` コード、JSON の
   **Response body**（ペットの一覧）、そして **Response headers**。

## 出力、翻訳、クリーンアップ

- 英語のガイドを
  `sample-guide/petstore-swagger-ui-guide.md` に書き出します。
- 英語ファイルを正典としたまま、`translate-markdown-ja` スキルで日本語の対応版
  `sample-guide/petstore-swagger-ui-guide.ja.md` を作成します。
- 最後の撮影のあと、失敗またはブロックされた実行のあとも含めて、`create-screenshot-guide`
  セッションを閉じます。`.playwright-cli/` 配下の一時ファイルはローカルの CLI アーティ
  ファクトであり、成果物の一部ではありません。
- サイトまたはネットワークが利用できない場合は、スクリーンショットやレスポンスをでっち上げ
  るのではなく、作業を止めて環境要因のブロッカーとして報告します。
