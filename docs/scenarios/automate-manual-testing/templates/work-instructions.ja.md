# 作業手順: Playwright CLI を使用した playwright.dev の検証

## 目的

Playwright CLI を使用して [playwright.dev](https://playwright.dev/)
上でユーザーに表示される5つの動作を検証し、提供された作業レポート
テンプレートに記入して結果を提出します。これは公開されている Playwright
公式ページに対する読み取り専用テストです。

## 実行ルール

- リポジトリルートからコマンドを実行します。
- `pnpm exec playwright-cli` を使用してプロジェクトローカルの CLI を実行し、
  インストール済みの Playwright CLI Agent Skill に従います。
- すべてのブラウザーコマンドで、名前付きブラウザーセッション
  `automate-manual-testing` を使用します。
- CLI が管理する新しいブラウザーを使用します。個人用ブラウザーにアタッチしたり、
  永続プロファイル、保存済み状態、Cookie、認証情報を使用したりしないでください。
- アクセシビリティスナップショットと、ロールおよびアクセシブル名に基づく
  ユーザー向けロケーターを優先します。CSS セレクターや XPath は使用しないでください。
- ナビゲーション後またはページ状態が大きく変化した後は、新しいスナップショットを
  取得します。古いスナップショットの一時的な要素参照を再利用しないでください。
- GitHub やその他の外部サービスへのリンクは開かないでください。サイト検索を使用したり、
  現在のスター数を検証したり、その他の動的なサードパーティーデータに依存したり
  しないでください。
- 確認した URL、タイトル、見出し、選択状態、表示コマンドなど、簡潔なテキストの
  エビデンスを記録します。レポートに未加工のスナップショット全体を含めないでください。
- 失敗後も安全に実行できる場合は、独立したチェックを続行します。復旧が必要な場合は、
  そのチェックで指定された開始ページに戻ります。
- この手順書やレポートテンプレートを変更しないでください。記入済みレポートは、
  依頼者が指定した出力パスに書き込みます。
- 失敗またはブロックされた実行の後も含め、クリーンアップ時に名前付きブラウザー
  セッションを閉じます。

## 結果ルール

各チェックに次のいずれか1つのステータスを割り当てます。

- `PASS`: チェックの期待結果がすべて確認されました。
- `FAIL`: チェックは最後まで実行されましたが、1つ以上の期待結果を確認できませんでした。
- `BLOCKED`: 環境、ネットワーク、CLI、または利用できない前提条件によって実行できず、
  チェックで確定的な結果を得られませんでした。

5つのチェックがすべてパスした場合のみ、全体ステータスを `PASS` とします。1つ以上の
チェックが失敗した場合は `FAIL` とします。失敗したチェックがなく、1つ以上のチェックが
ブロックされた場合にのみ `BLOCKED` を使用します。

## チェック

### MT-01: ホームページの識別情報

1. 名前付きセッションで `https://playwright.dev/` を開きます。
2. 正規化されたページ URL が `https://playwright.dev/` であることを確認します。
3. ドキュメントタイトルに `Playwright` が含まれることを確認します。
4. 表示されているレベル1の見出しが
   `Playwright enables reliable web automation` で始まることを確認します。

確認した URL、タイトル、見出しをエビデンスとして記録します。

### MT-02: 製品ラインアップ

1. `https://playwright.dev/` から開始します。
2. ページに3つの製品見出し `Playwright Test`、`Playwright CLI`、
   `Playwright MCP` がすべて表示されていることを確認します。

確認した3つの名前、または該当範囲のスナップショット抜粋をエビデンスとして記録します。

### MT-03: Get started のナビゲーション

1. `https://playwright.dev/` から開始します。
2. `Get started` という名前のリンクを操作します。
3. ナビゲーション先が `https://playwright.dev/docs/intro` であることを確認します。
4. 表示されているレベル1の見出しが `Installation` であることを確認します。

移動先 URL と見出しをエビデンスとして記録します。

### MT-04: pnpm のインストール手順

1. `https://playwright.dev/docs/intro` から開始します。
2. `Installing Playwright` セクションと、そのパッケージマネージャータブを探します。
3. そのセクション内で `pnpm` という名前のタブを操作します。ページには他にも
   パッケージマネージャーのタブグループがあるため、ページ上の位置に依存せず、
   現在のセクションに限定したスナップショットから対象のコントロールを特定します。
4. 対象の `pnpm` タブが選択されていることを確認します。
5. 同じセクションに表示されるインストールコマンドが
   `pnpm create playwright` で始まることを確認します。

タブの選択状態と、表示された正確なコマンドをエビデンスとして記録します。

### MT-05: 次のドキュメントページ

1. `https://playwright.dev/docs/intro` から開始します。
2. アクセシブル名に `Writing tests` を含む次ページへのリンクを操作します。
3. ナビゲーション先が
   `https://playwright.dev/docs/writing-tests` であることを確認します。
4. 表示されているレベル1の見出しが `Writing tests` であることを確認します。
5. ページに、Playwright のテストはアクションを実行し、期待値に対して状態を
   アサートするという説明があることを確認します。

移動先 URL、見出し、簡潔な導入文をエビデンスとして記録します。

## 提出とクリーンアップ

提供されたレポートテンプレートのすべてのプレースホルダーを埋めます。集計件数の合計を
5件とし、詳細ステータスと一致させます。サイトの変化、環境上の制約、予期しない動作は
Findings に記載し、確認した失敗を合格サンプルとして扱わないでください。

最後のエビデンスを収集した後に `automate-manual-testing` を閉じ、クリーンアップが
成功したかを記録します。`.playwright-cli/` 内の一時ファイルはローカル CLI の
生成物であり、レポートの添付ファイルではありません。
