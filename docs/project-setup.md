# Node.js Project Setup with pnpm

This guide explains how to initialize this repository as a Node.js project for
documenting and trying typical Playwright CLI workflows. The Playwright CLI is
installed with pnpm as a project development dependency. A global Playwright CLI
installation is neither required nor recommended for this repository.

## Prerequisites

Install the following tools before setting up the project:

- [Node.js](https://nodejs.org/) 20 or newer. This is the minimum version in the
  official Playwright CLI prerequisites.
- A current stable version of [pnpm](https://pnpm.io/installation) that supports
  the installed Node.js version.
- Git.
- A coding agent such as GitHub Copilot or Claude Code when using the CLI through
  an agent.

Confirm the installed versions:

```sh
node --version
pnpm --version
git --version
```

The Node.js version must start with `v20` or a newer major version. A Node.js
version manager can be used if the installed version is older. Install pnpm with
one of the methods in the official pnpm installation guide if `pnpm --version`
fails.

## Clone the repository

```sh
git clone https://github.com/ks6088ts-labs/template-playwright.git
cd template-playwright
```

Run all remaining commands from the repository root.

## Initialize the pnpm project

This section is for the maintainer performing the initial repository setup. If
`package.json` and `pnpm-lock.yaml` are already committed, skip to
[Set up an existing clone](#set-up-an-existing-clone).

Create the package manifest:

```sh
pnpm init
```

This repository contains examples and documentation rather than a package that
should be published to a package registry. Mark the package as private when
adding the scripts later in this guide.

## Install Playwright CLI locally

Install the latest Playwright CLI as an exact development dependency:

```sh
pnpm add --save-dev --save-exact @playwright/cli@latest
```

This command creates or updates both files below:

- `package.json` records `@playwright/cli` in `devDependencies`.
- `pnpm-lock.yaml` locks the complete dependency tree for reproducible
  installs.

Commit both files. Do not commit `node_modules/`; it is already excluded by this
repository's `.gitignore`.

Using `@latest` here is intentional only for the initial setup or an explicit
upgrade. Normal installations must use the committed lockfile. Do not substitute
`pnpm dlx` for this command because `pnpm dlx` runs a temporary package without
recording it as a project dependency.

## Add pnpm scripts

Set `private` to `true` and add these entries to the `scripts` object in
`package.json`:

```json
{
  "private": true,
  "scripts": {
    "pw": "playwright-cli",
    "pw:help": "playwright-cli --help",
    "pw:install-browser": "playwright-cli install-browser",
    "pw:install-skills": "playwright-cli install --skills=agents"
  }
}
```

Keep the fields generated by `pnpm init` and the `devDependencies` generated by
`pnpm add`; the snippet above shows only the fields that need to be added or
updated.

pnpm scripts automatically place `node_modules/.bin` on `PATH`. Therefore, these
commands use the version installed in this project:

```sh
pnpm run pw:help
pnpm run pw -- <command> [options]
```

The `--` separator passes every following argument to `playwright-cli`.
For direct access to another CLI command, `pnpm exec` also resolves the local
binary:

```sh
pnpm exec playwright-cli --version
```

Do not use either of the following forms in this repository:

```sh
pnpm add --global @playwright/cli
playwright-cli --help
```

The first command creates an unmanaged global installation. The second command
depends on a global `PATH` entry when it is run directly from a shell. Using the
pnpm scripts or `pnpm exec` keeps the CLI version tied to `pnpm-lock.yaml`.

## Install a browser

The CLI downloads a browser automatically on first use. Installing it explicitly
during setup makes the environment ready before running an example:

```sh
pnpm run pw:install-browser
```

This installs the default browser, Chromium. Other supported forms include:

```sh
# Install a specific browser.
pnpm run pw -- install-browser firefox

# Install Chromium and required system dependencies on Linux.
pnpm run pw -- install-browser --with-deps

# Preview browser installation without making changes.
pnpm run pw -- install-browser --dry-run

# List browsers available from installed Playwright packages.
pnpm run pw -- install-browser --list
```

The `--with-deps` option is intended for Linux environments and may require
permission to install operating-system packages.

## Install coding-agent skills

Playwright CLI can install skills that give supported coding agents richer
context about its commands:

```sh
pnpm run pw:install-skills
```

Review the files created by this command before committing them because the
relevant skill location can depend on the coding agent in use. Installing skills
is optional; an agent can also inspect `playwright-cli --help` when needed.

## Verify the setup

Confirm that pnpm resolves the project-local dependency and that the CLI starts:

```sh
pnpm list @playwright/cli --depth 0
pnpm run pw:help
```

The first command should show `@playwright/cli` under this repository, and the
second should print the CLI help without a `command not found` error.

Check the files that will be committed:

```sh
git status --short
```

At minimum, the initial Node.js setup should include `package.json` and
`pnpm-lock.yaml`.

## Set up an existing clone

After the package files have been committed, contributors should not repeat the
initialization steps. Use the lockfile to install exactly the dependency versions
selected by the repository:

```sh
git clone https://github.com/ks6088ts-labs/template-playwright.git
cd template-playwright
pnpm install --frozen-lockfile
pnpm run pw:install-browser
pnpm run pw:help
```

Use `pnpm install --frozen-lockfile` in local clean setups and continuous
integration. It installs from `pnpm-lock.yaml` without updating the lockfile and
fails when `package.json` and `pnpm-lock.yaml` do not agree, which prevents
accidental dependency drift. pnpm enables frozen lockfile behavior by default in
recognized CI environments when a lockfile is present, but specifying the option
keeps local and CI instructions consistent.

## Upgrade Playwright CLI

Perform upgrades deliberately in a separate change:

```sh
pnpm add --save-dev --save-exact @playwright/cli@latest
pnpm run pw:help
```

Review the release notes and the changes to both pnpm package files before
committing the upgrade.

## Troubleshooting

### The Node.js version is unsupported

Install Node.js 20 or newer, switch the active version, and run
`pnpm install --frozen-lockfile` again. Also confirm that the installed pnpm version
supports the selected Node.js version.

### The CLI cannot be found

Run `pnpm install --frozen-lockfile`, then invoke the CLI through
`pnpm run pw:help`, `pnpm run pw -- <command>`, or `pnpm exec playwright-cli`.
Do not solve this by installing the package globally.

### A browser executable is missing

Run `pnpm run pw:install-browser`. On a Linux host that also lacks system
libraries, run `pnpm run pw -- install-browser --with-deps` with the permissions
required by that environment.

### The frozen install reports a lockfile mismatch

Do not delete the lockfile. If dependency changes were intentional, run
`pnpm install`, review the resulting `pnpm-lock.yaml`, and commit it together with
`package.json`. Otherwise, restore the package files from the repository and
retry `pnpm install --frozen-lockfile`.
